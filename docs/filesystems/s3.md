# S3 ファイルシステム仕様

## 概要

S3 ファイルシステムは、Amazon S3（およびS3互換ストレージ）からファイルを読み込むためのドライバーです。

## ドライバー名

```yaml
driver: s3
```

## 必須パラメータ

| パラメータ | 型 | 説明 |
|-----------|-----|------|
| bucket | string | S3 バケット名 |
| region | string | AWS リージョン（例: `us-east-1`, `ap-northeast-1`） |

## オプションパラメータ

| パラメータ | 型 | デフォルト | 説明 |
|-----------|-----|----------|------|
| root | string | "" | バケット内のルートパス（このパスより上位には遡れない） |
| access_key_id | string | "" | AWS アクセスキー ID（省略時は環境変数または IAM ロールから取得） |
| secret_access_key | string | "" | AWS シークレットアクセスキー（省略時は環境変数または IAM ロールから取得） |
| session_token | string | "" | AWS セッショントークン（一時的な認証情報使用時） |
| endpoint | string | "" | カスタムエンドポイント（MinIO など S3 互換ストレージ用） |
| use_path_style | bool | false | パススタイルアクセスを使用（S3 互換ストレージで必要な場合あり） |
| transform.read | string | null | 読み込み時の変換方法（`dotenv`、`json` など） |
| transform.write | string | null | 書き込み時の変換方法（現在未使用） |
| timeout | duration | "30s" | リクエストタイムアウト |

## 認証方法

S3 ファイルシステムは、以下の優先順位で認証情報を取得します：

### 1. 設定ファイルでの明示的な指定

```yaml
namespaces:
  default:
    s3config:
      driver: s3
      args:
        bucket: my-config-bucket
        region: ap-northeast-1
        access_key_id: AKIAIOSFODNN7EXAMPLE
        secret_access_key: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

⚠️ **セキュリティ警告**: 認証情報を設定ファイルに直接記載するのは開発環境のみにしてください。本番環境では環境変数または IAM ロールを使用してください。

### 2. 環境変数

```bash
export AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
export AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
export AWS_SESSION_TOKEN=FwoGZXIvYXdzE... # オプション（一時認証情報使用時）
export AWS_REGION=ap-northeast-1
```

### 3. 共有認証情報ファイル

```bash
# ~/.aws/credentials
[default]
aws_access_key_id = AKIAIOSFODNN7EXAMPLE
aws_secret_access_key = wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY

# ~/.aws/config
[default]
region = ap-northeast-1
```

### 4. IAM ロール（推奨：本番環境）

EC2 インスタンスや ECS タスクで実行する場合、IAM ロールから自動的に認証情報を取得します。設定ファイルには認証情報を記載する必要がありません。

```yaml
namespaces:
  production:
    s3config:
      driver: s3
      args:
        bucket: prod-config-bucket
        region: ap-northeast-1
        # 認証情報は IAM ロールから自動取得
```

## セキュリティ

### パストラバーサル防止

`root` で指定されたパスより上位には遡れません。

```yaml
args:
  bucket: my-bucket
  root: config/production  # このパスより上位にはアクセス不可
```

ユーザーが `../../secrets/api-key` のようなパスを指定しても、`config/production` より上位にはアクセスできません。

### 相対パスのみ

ファイルパスは相対パスのみ受け付けます。絶対パス（`/etc/passwd`）やチルダパス（`~/config`）は拒否されます。

### バケットポリシーとの連携

kvtool は S3 のバケットポリシーや IAM ポリシーに従います。適切なアクセス制御を設定してください。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::my-config-bucket/config/*"
    }
  ]
}
```

## 設定例

### 基本的な設定

```yaml
version: 0.1
namespaces:
  default:
    s3config:
      driver: s3
      args:
        bucket: my-config-bucket
        region: ap-northeast-1
        root: config
```

### S3 互換ストレージ（MinIO）

```yaml
version: 0.1
namespaces:
  default:
    minio:
      driver: s3
      args:
        bucket: configs
        region: us-east-1
        endpoint: http://localhost:9000
        use_path_style: true
        access_key_id: minioadmin
        secret_access_key: minioadmin
```

### 複数環境の設定

```yaml
version: 0.1
namespaces:
  development:
    s3config:
      driver: s3
      args:
        bucket: dev-config-bucket
        region: ap-northeast-1
        root: config/dev

  staging:
    s3config:
      driver: s3
      args:
        bucket: staging-config-bucket
        region: ap-northeast-1
        root: config/staging

  production:
    s3config:
      driver: s3
      args:
        bucket: prod-config-bucket
        region: ap-northeast-1
        root: config/prod
```

### dotenv 変換を使用

```yaml
version: 0.1
namespaces:
  default:
    s3env:
      driver: s3
      args:
        bucket: my-env-bucket
        region: us-west-2
        root: environments
        transform:
          read: dotenv
```

## 使用例

### 基本的な取得

```bash
# S3 から設定ファイルを取得
kvtool store load s3config/app.json

# 環境を指定して取得
kvtool store load s3config/database.json -n production

# JSON として取得して jq で加工
kvtool store load s3config/app.json | jq '.database.host'
```

### dotenv ファイルの取得

```bash
# S3 上の .env ファイルを JSON に変換して取得
kvtool store load s3env/production.env

# 特定の値だけ抽出
kvtool store load s3env/production.env | jq -r '.DATABASE_URL'
```

### CI/CD での利用

```yaml
# GitHub Actions の例
steps:
  - name: Install kvtool
    run: |
      curl -L https://github.com/yourusername/kvtool/releases/latest/download/kvtool-linux-amd64 -o kvtool
      chmod +x kvtool
      sudo mv kvtool /usr/local/bin/

  - name: Configure AWS credentials
    uses: aws-actions/configure-aws-credentials@v1
    with:
      role-to-assume: arn:aws:iam::123456789012:role/GitHubActionsRole
      aws-region: ap-northeast-1

  - name: Get configuration from S3
    run: |
      kvtool store load s3config/app.json -n production > config.json
      cat config.json
```

### Docker での利用

```dockerfile
FROM golang:1.21-alpine AS builder
RUN apk add --no-cache curl
RUN curl -L https://github.com/yourusername/kvtool/releases/latest/download/kvtool-linux-amd64 -o /usr/local/bin/kvtool
RUN chmod +x /usr/local/bin/kvtool

FROM alpine:latest
COPY --from=builder /usr/local/bin/kvtool /usr/local/bin/kvtool
COPY .kvtool.yml /app/.kvtool.yml
WORKDIR /app

# S3 から設定を取得してアプリケーションを起動
CMD kvtool store load s3config/app.json > config.json && ./app
```

## エラーハンドリング

### バケットが存在しない

```
Error: bucket "non-existent-bucket" does not exist
```

対処法: バケット名と region を確認してください。

### 認証エラー

```
Error: access denied: failed to get object from S3
```

対処法:
- AWS 認証情報が正しいか確認
- IAM ポリシーで `s3:GetObject` 権限があるか確認
- バケットポリシーでアクセスが許可されているか確認

### オブジェクトが存在しない

```
Error: object "config/app.json" not found in bucket "my-bucket"
```

対処法: S3 バケット内にファイルが存在するか確認してください。

### タイムアウト

```
Error: request timeout after 30s
```

対処法: `timeout` パラメータを増やすか、ネットワーク接続を確認してください。

```yaml
args:
  bucket: my-bucket
  region: ap-northeast-1
  timeout: 60s  # タイムアウトを60秒に延長
```

### S3 互換ストレージでのエラー

```
Error: failed to connect to endpoint
```

対処法: `use_path_style: true` を設定してください。

```yaml
args:
  endpoint: http://localhost:9000
  use_path_style: true
```

## パフォーマンスと制限事項

### キャッシング

現在のバージョンでは、S3 から取得したファイルはキャッシュされません。毎回 API リクエストが発生します。

将来的な改善案:
- ローカルキャッシュの実装
- ETag ベースの更新検知
- TTL ベースのキャッシュ無効化

### レート制限

S3 は以下のレート制限があります：
- GET リクエスト: 5,500 requests/second per prefix
- PUT リクエスト: 3,500 requests/second per prefix

大量のファイルを頻繁に取得する場合は、キャッシュの実装や batch 取得を検討してください。

### ファイルサイズ

現在のバージョンでは、取得したファイルを全てメモリに展開します。大きなファイル（数百MB以上）を扱う場合はメモリ使用量に注意してください。

## ベストプラクティス

### 1. 本番環境では IAM ロールを使用

```yaml
# ❌ 悪い例: 認証情報をハードコード
production:
  s3config:
    driver: s3
    args:
      access_key_id: AKIAIOSFODNN7EXAMPLE
      secret_access_key: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY

# ✅ 良い例: IAM ロールに任せる
production:
  s3config:
    driver: s3
    args:
      bucket: prod-config-bucket
      region: ap-northeast-1
```

### 2. root パスでスコープを制限

```yaml
# セキュリティのため、アクセス可能なパスを制限
args:
  bucket: shared-bucket
  root: myapp/config  # myapp/config 配下のみアクセス可能
```

### 3. 環境ごとに namespace を分ける

```yaml
namespaces:
  dev:
    s3config:
      driver: s3
      args:
        bucket: dev-bucket
        region: ap-northeast-1

  prod:
    s3config:
      driver: s3
      args:
        bucket: prod-bucket
        region: ap-northeast-1
```

### 4. タイムアウトを適切に設定

```yaml
args:
  timeout: 10s  # ネットワーク状況に応じて調整
```

## S3 互換ストレージのサポート

kvtool は以下の S3 互換ストレージをサポートします：

- **MinIO**: オープンソースのオブジェクトストレージ
- **Wasabi**: 低コストのクラウドストレージ
- **Backblaze B2**: S3 互換 API を提供
- **DigitalOcean Spaces**: S3 互換のオブジェクトストレージ
- **Cloudflare R2**: エグレス料金無料のストレージ

### MinIO の設定例

```yaml
namespaces:
  local:
    minio:
      driver: s3
      args:
        bucket: kvtool-configs
        region: us-east-1  # MinIO では固定値でOK
        endpoint: http://localhost:9000
        use_path_style: true
        access_key_id: minioadmin
        secret_access_key: minioadmin
```

### Cloudflare R2 の設定例

```yaml
namespaces:
  default:
    r2:
      driver: s3
      args:
        bucket: my-configs
        region: auto
        endpoint: https://<account-id>.r2.cloudflarestorage.com
        access_key_id: <r2-access-key-id>
        secret_access_key: <r2-secret-access-key>
```
